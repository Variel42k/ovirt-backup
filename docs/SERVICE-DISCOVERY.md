# Поиск сервисов и резервных копий ПО

Раздел **Инфраструктура → Поиск сервисов** строит карту «приложение → ВМ →
существующая копия в BACKUPDATA». Поиск только читает данные и работает в три
уровня.

## 1. HTTP и TLS

Служба берёт из выбранных подключений адрес Manager/Engine, адреса
гипервизоров и адреса работающих ВМ, затем один раз обращается к настроенным
портам. Из сертификата, заголовков и первых 64 КиБ страницы она определяет имя
и тип приложения. Переходы по ссылкам не выполняются, пароли и cookie не
передаются. Docker, CNI, virbr и link-local адреса отбрасываются.

Для KVM адреса берутся у qemu-guest-agent, а при его отсутствии — из DHCP lease
libvirt. Для oVirt/РЕД Виртуализации используются reported devices гостевого
агента.

Reverse proxy, балансировщики и внешние сервисы могут не принадлежать ни одной
ВМ из инвентаря. Область поиска настраивается прямо на странице: раскройте
**Область поиска**, перечислите цели и нажмите **Сохранить**. Поддерживаются:

- одно или несколько подключений виртуализации; в списке видны их адреса,
  пустой выбор означает все включённые подключения;
- точное DNS-имя или URL;
- числовой DNS-диапазон `node-[01-20].example.local`;
- IPv4 CIDR `10.249.254.0/24`;
- включительный диапазон `10.249.254.10-10.249.254.50`.

Стандартный режим не требует DNS-имён, диапазонов или адресов в YAML. Он
динамически получает Manager/Engine, гипервизоры, ВМ и их reported IP из
инвентаря выбранных подключений. Из приватных IPv4-адресов инвентаря также
строятся уникальные `/24` автосети: благодаря этому находятся reverse proxy и
другие хосты той же сети, даже если они не представлены отдельной ВМ. Если
работающая ВМ не сообщает IP, поиск дополнительно пытается разрешить её
инвентарное имя через DNS. Публичные адреса в автосети не разворачиваются.

Каждый динамический адрес и hostname проверяется на списке **Порты поиска**.
Список редактируется в web и принимает отдельные значения и диапазоны,
например `80, 443, 3000-3010`; после разворачивания допускается до 256 портов.
URL с явной схемой сохраняет точную проверку своего порта и пути, но его
hostname дополнительно проверяется на всех портах списка. Поэтому
`http://adv-gitlab.example.org/` не ограничивает поиск только портом 80.
Имена, найденные автоматически в HTTP `Location` и TLS-сертификатах при
обращении к IP, проходят такую же повторную проверку с правильными Host/SNI.

Ручные DNS-цели и диапазоны являются только дополнительным режимом для
внешних сетей. Он включается отдельным переключателем, поэтому большой старый
диапазон не замедляет стандартный поиск после обновления.

Настройки сохраняются в PostgreSQL и начинают действовать со следующего
поиска. Кнопка **Вернуть из YAML** удаляет web-переопределение. Те же начальные
значения можно задать в файле:

```yaml
discovery:
  # Пусто — все включённые подключения виртуализации.
  server_ids: []
  scan_additional_targets: true
  web_ports: [80, 443, 8080, 8081, 8443]
  web_targets:
    - https://adv-gitlab.advengineering.ru
  web_networks:
    - 10.249.254.0/24
  web_max_addresses: 1024
```

При `scan_additional_targets: false` поля `web_targets` и `web_networks` не
участвуют в поиске. Точный URL проверяется на указанной схеме, порту и пути,
после чего его hostname проверяется на всех `web_ports`. Имя без схемы также
проверяется на всех `web_ports`. Диапазоны никогда не выводятся из маршрутов
автоматически. Общий размер развёрнутых DNS-имён и IPv4-адресов ограничивает
настраиваемый `web_max_addresses` в диапазоне 1–65536. Для больших или
фильтруемых сетей уменьшите `web_timeout` и при необходимости увеличьте
`max_parallel` в допустимых пределах.

`web_max_addresses` ограничивает и автоматически построенные сети. В область
попадают только полные `/24`; если лимита недостаточно, лишние сети
пропускаются с предупреждением в журнале. Точные адреса ВМ при этом всё равно
проверяются.

Выбор подключения ограничивает весь стандартный поиск: адрес его Manager или
Engine, известные гипервизоры и ВМ. Для standalone KVM адресом виртуализации
считается `ssh_host`; он также проверяется на `web_ports`. Отключённые
подключения не сканируются, даже если их UUID остался в сохранённой области.
Сначала сохраняются результаты динамического инвентаря, и только затем
запускаются дополнительные диапазоны. Поэтому на странице видны число ВМ и
найденные стандартным поиском сервисы, даже пока большой внешний диапазон ещё
обрабатывается.

Размер таблиц выбирается в этой же панели (10, 20, 50, 100 или 200 строк).
Выбор хранится в браузере; навигация по страницам находится внизу таблицы.

Во время поиска верхний информационный блок показывает текущий этап, число
выполненных проверок и шкалу прогресса. Пока объём очередного этапа ещё не
известен, шкала работает в неопределённом режиме. Страница запрашивает состояние
каждые две секунды, поэтому прогресс остаётся виден после перезагрузки страницы
и для поиска, запущенного автоматически или другим пользователем.

## 2. BACKUPDATA

Создайте SMB-хранилище для `\\truenas2.advengineering.ru\BACKUPDATA` с
отдельной учётной записью только на чтение. Скопируйте его `id` и укажите:

```yaml
discovery:
  enabled: true
  interval: 24h
  backup_storage_target_id: "UUID-хранилища"
  backup_prefix: ""
  backup_max_age: 48h
```

По каждому каталогу показываются последний файл, дата и общий объём. Имя
каталога сопоставляется с продуктом, DNS-именем и именем ВМ. Копия старше
`backup_max_age` подсвечивается и создаёт предупреждение.

## 3. Карта из гостя

Необязательный уровень находит контейнеры, работающие systemd-службы, пути
данных, сетевые монтирования и строки cron, связанные с резервным копированием.
Он нужен за reverse proxy, где HTTP-сертификат показывает только прокси.

Установка ограниченного helper и ключа описана в
`deploy/discovery/README.md`. Затем включите:

```yaml
discovery:
  guest:
    enabled: true
    username: jhvirt-discovery
    private_key_file: /run/secrets/discovery_private_key
    known_hosts_file: /app/config/discovery_known_hosts
```

Ключ обязан быть отдельным от ключей гипервизоров и СУБД. `known_hosts`
проверяется строго; автоматическое принятие неизвестного ключа не предусмотрено.

## API

- `GET /api/v1/discovery` — последний сохранённый снимок;
- `POST /api/v1/discovery/scan` — выполнить новый поиск сейчас;
- `GET /api/v1/discovery/settings` — эффективная область поиска и её размер;
- `PUT /api/v1/discovery/settings` — сохранить web-переопределение;
- `DELETE /api/v1/discovery/settings` — вернуться к YAML.

Автоматический поиск запускается только ведущим экземпляром службы. Ручной
запрос защищён от параллельного запуска и возвращает `409 discovery_busy`, если
поиск уже идёт.
