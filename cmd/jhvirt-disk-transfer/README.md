# Мастер поиска и переноса дисков oVirt

`jhvirt-disk-transfer` — интерактивное приложение на Go для терминала. Запускается на **исходном Linux-хосте**, где уже доступен файловый домен oVirt. Для поиска через API использует существующий клиент `virt-manager`. Для подготовки образов использует системный `qemu-img`, для доставки — OpenSSH и `rsync`. В интерфейсе не нужно вводить команды, скрипты или суммы SHA‑256.

## Возможности и границы

- Ищет ВМ или диск в Engine по имени (в том числе части имени) или UUID. Позволяет выбрать несколько дисков ВМ, например `1,3`. После выбора мастер сопоставляет UUID с уже доступными файловыми доменами на исходном хосте и для каждого диска предлагает расположения. Без доступа к Engine можно найти диск локально по UUID; для цепочки потребуется вручную указать верхний том, подтверждённый администратором.
- Показывает отдельно UUID диска, домен, верхний том и найденную цепочку. **Склейка** — сборка верхнего QCOW2 вместе с родителями в один автономный образ. Несколько независимых дисков ВМ **не объединяются**: каждый диск становится своим файлом. Оригинал, снапшоты, метаданные и настройки ВМ не изменяются.
- Создаёт файлы только в новом закрытом подкаталоге указанного каталога подготовки. Можно указать локальный диск или уже смонтированный частный сетевой каталог. Во втором случае сборка и запись идут сразу на сетевую ФС, без отдельной полной локальной копии. Это не копирование работающей ВМ.
- Доставляет проверенные файлы в отдельный каталог получателя через `rsync` по SSH или оставляет в каталоге подготовки. **Не регистрирует диски в целевом oVirt, не подключает их и не запускает ВМ.** Для регистрации используйте штатную загрузку в портале после проверки файлов. Не копируйте их в `images` управляемого домена.

Поддерживаются файловые домены и обычные тома `RAW`/`QCOW2`, доступные как файлы в структуре `домен/images/UUID-диска/UUID-тома`. Цепочки, выходящие за пределы каталога диска (например, с базовым образом шаблона в другом каталоге), Direct LUN и живой экспорт не поддерживаются. Если найдено несколько копий, мастер не выбирает одну сам: укажите конкретный домен.

## Запуск

Из корня репозитория на машине сборки (версия Go — из `go.mod`):

```bash
go test ./cmd/jhvirt-disk-transfer ./internal/ovirt
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o jhvirt-disk-transfer ./cmd/jhvirt-disk-transfer
```

Скопируйте бинарник по уже настроенному SSH на исходный Linux-хост и дайте владельцу право запуска. Для `aarch64` соберите с `GOARCH=arm64`. Установка Go на гипервизор не нужна. Для подготовки нужен `qemu-img`, для доставки — `ssh` на источнике, `rsync` с обеих сторон и проверенный ключ хоста получателя в `known_hosts`. На шаге входа по SSH нажмите Enter для ключа или введите `2` для пароля, если его принимает получатель. OpenSSH запрашивает пароль в терминале без отображения. Выход из мастера — Ctrl+C. Engine работает по HTTPS с проверкой сертификата.

Из Windows откройте PowerShell и войдите на источник, например `ssh -t -o StrictHostKeyChecking=yes root@source-hv.example.test`. Запускайте мастер в этой SSH-сессии. Источник устанавливает соединение с получателем и передаёт образы напрямую.

После ввода HTTPS-адреса Engine мастер проверяет сертификат до запроса логина и пароля. Сначала он использует системное хранилище доверенных CA. Если издатель сертификата неизвестен, мастер пробует `/etc/pki/vdsm/certs/cacert.pem` и `/etc/pki/ovirt-engine/ca.pem`. При успехе он показывает использованный источник доверия и сразу переходит к логину. Если автоматическая проверка не прошла из-за неизвестного издателя, укажите PEM-файл доверенного CA, полученный у администратора, или нажмите Enter для отмены. При ошибке имени сертификата используйте DNS-имя Engine из сертификата.

Сначала посмотрите план. Образы и каталоги не создаются. При выборе SSH-получателя мастер читает монтирования, показывает свободное место и проверяет указанный путь:

```bash
./jhvirt-disk-transfer --dry-run
```

Для выполнения запустите `./jhvirt-disk-transfer` и пройдите шаги:

1. **Найти исходник.** Вариант `1` ищет по ВМ в Engine, `2` ищет диск в Engine, `3` ищет по известному UUID диска локально. В режиме `1` укажите исходный Engine, например `https://engine-source.example.test`, выберите ВМ и номера её дисков. Мастер предложит пути к найденным томам на уже смонтированных файловых доменах. Для поиска без Engine скопируйте UUID из карточки нужного диска. Если нужного расположения нет в меню, введите абсолютный путь к доступному экспорту или каталогу домена.
2. **Выбрать формат.** Для каждого диска мастер покажет, нашёл ли он один том или цепочку. Нажмите Enter для автовыбора. Одиночный том сохранится в исходном формате, цепочка соберётся в отдельный автономный QCOW2. Если получателю нужны только QCOW2, выберите `1`. Вариант `2` сохраняет исходные форматы и доступен, когда все выбранные диски состоят из одного тома.
3. **Выбрать место.** Мастер покажет доступное место на файловой системе каждого предложенного каталога на источнике и получателе. Для пути, введённого вручную, он покажет место после проверки каталога. Выбирайте согласованный каталог вне `images` и структуры домена. Мастер создаст внутри `ovirt-transfer-*` с закрытыми правами. Вариант доставки `1` оставляет файлы там. Вариант `2` запрашивает `пользователь@хост` (например, `root@target-hv.example.test`) и предлагает каталог получателя. Введите абсолютный путь вручную, если нужен отдельный подкаталог. Для SSH используйте пути из букв латиницы, цифр, точек, дефисов и знаков подчёркивания.
4. **Подтвердить.** Проверьте в исходном Engine, что ВМ, которые используют выбранные диски, выключены и не запустятся, а задачи со снапшотами и перемещением завершены. Введите `COPY`. При поиске через API мастер дополнительно проверит статус диска, активный том и сообщённые Engine привязки ВМ до чтения и перед публикацией. Без API подтверждение полностью на операторе. Это не блокировка Engine от чужих действий.
5. **Проверить результат.** `qemu-img` сверяет метаданные цепочки, структуру QCOW2, виртуальный размер и логическое содержимое (`compare`). Только затем появляется готовый файл. При доставке по SSH мастер сначала публикует всю партию, затем проверяет наличие и размер каждого файла у получателя и удаляет подготовленные образы из рабочего каталога на источнике. В рабочем каталоге остаётся файл задания. Если выбрано «оставить файлы в каталоге подготовки», мастер сохраняет локальные образы.

## Прямая передача одиночных RAW

В поиске через Engine (пункты `1` и `2`) выберите диски из одного RAW-тома. В меню формата нажмите Enter или выберите сохранение исходного формата. На следующем шаге **«Способ копирования»** выберите `2 — передать исходные RAW напрямую по SSH`. Мастер запишет файлы сразу на получателя и сохранит файл задания в `/var/tmp/ovirt-transfer-<номер>` на источнике.

Держите связанные ВМ в состоянии `down`, включая паузы после разрыва, и дождитесь завершения задач со снапшотами и перемещением. Мастер сверяет активный том, состояние ВМ и идентификатор и метаданные файла перед отправкой, после чтения и перед публикацией. `rsync` проверяет переданные данные своим контрольным алгоритмом. Для цепочек и преобразования в QCOW2 используйте режим подготовки.

## Возобновление SSH-передачи

После проверки исходных RAW или подготовки локальных образов мастер сохраняет задание. При временном обрыве связи работающий мастер сам повторяет передачу до пяти раз. Вход по ключу позволяет восстановить соединение без участия оператора. При входе по паролю OpenSSH снова запросит его, если прежний сеанс закрылся.

Если процесс завершён, запустите мастер снова. Единственное зарегистрированное незавершённое задание продолжится автоматически. Для нескольких заданий мастер предложит выбрать номер или перейти в главное меню клавишей `0`. Выбор также доступен через пункт `4`, а для задания из нестандартного каталога можно ввести путь вручную. Для входа мастер запросит нужные учётные данные. Запуск с `--new` открывает главное меню. Если передача уже выполняется, обычный запуск тоже открывает меню.

Сохраняйте рабочий каталог задания на источнике и `.part` на получателе до подтверждения доставки. Все повторные попытки используют одно задание.

Рабочий каталог также можно передать сразу аргументом:

```bash
./jhvirt-disk-transfer --resume /data/storage/staging/ovirt-transfer-123456789
```

Снова выберите способ входа по SSH. Для прямой передачи укажите напечатанный мастером каталог в `/var/tmp` и войдите в исходный Engine, когда мастер попросит. Если активный том или исходный файл изменился, создайте новое задание. `rsync` повторно использует сохранённые блоки неполного файла и пропускает уже переданные образы. Если партия уже опубликована, мастер сверяет файлы у получателя и завершает предусмотренную очистку. Если Ctrl+C прервал склейку или преобразование `qemu-img` до создания файла задания, подготовку нужно начать заново.
