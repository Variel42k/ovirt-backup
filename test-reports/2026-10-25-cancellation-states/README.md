# Подробности отмены по состояниям ВМ — 25.10.2026

Окно «Отмена и возврат» доработано в проекте. На стенд изменения не устанавливались;
команды реальным ВМ не отправлялись. Состояние миграции отделено от питания ВМ:
«Приостановлена» у миграции не означает, что гостевая ВМ находится на паузе.

Для каждой ВМ показаны:

- Источник и цель с именами подключений.
- Текущее питание, прочитанное из Engine, и сохранённое начальное питание источника.
- Ожидаемый результат выбранного действия для каждого гостя.
- Порядок выполнения, сохранение/удаление дисков, судьба новых данных цели,
  последующие блокировки и возможность продолжения.
- Пропуск неприменимых задач в группе и число затронутых ВМ.

Кнопка подтверждения называет действие: например «Вернуть источник, сохранить
цель». Удаление выделено отдельной красной кнопкой. Кнопка закрытия окна называется
«Закрыть». На узком экране прокручивается содержимое, кнопки остаются доступны.

## Семантика питания

| Действие | Источник | Цель |
|---|---|---|
| Пауза | Новые команды питания не отправляются | Новые команды питания не отправляются; незавершённая цель при создании может быть удалена очисткой |
| Выключить обе ВМ | Штатно выключается, диски сохраняются | Штатно выключается, ВМ и диски сохраняются |
| Вернуть источник, сохранить цель | Выключенный запускается, если работал в начале; уже работающий не перезапускается | Выключается, данные остаются на её дисках, блокировки миграции сохраняются |
| Вернуть источник, удалить цель | Та же проверка питания, после подтверждения удаления цели | Удаляется с дисками; новые данные цели теряются; блокировки снимаются |

Изначально выключенный источник не запускается. Если его включили вручную,
возврат сам по себе не выключает его. Пауза источника этим действием не снимается.
Изменения цели обратно в источник не копируются. Ошибка не откатывает уже
выполненные шаги; уже принятые Engine команды могут завершиться после запроса паузы.

Новый `GET /vm-transfers/{id}/cancellation-state` читает состояния без изменения
записи миграции или отправки команд ВМ. `target_exists: null` означает неизвестность,
а не отсутствие цели. После потерянного ответа создания ищется ВМ с меткой операции.
Если создание цели ещё не начиналось, это явно отмечено как сведения записи переноса.

## Проверки

- `npm run build` — успешно, TypeScript и production-сборка.
- 58/58 браузерных сценариев production-интерфейса — успешно на 1440×1000
  и 390×844, без пропусков и нестабильных результатов.
- После заключительного уточнения текстов повторены 22/22 сценария управления
  отменой — успешно.
- `go vet ./...` и `go test ./...` — успешно на Linux, отдельный временный
  PostgreSQL и изолированные схемы. Рабочая БД стенда не использовалась.
- Новые серверные проверки: живое питание без побочных действий, неизвестность
  при недоступном Engine, ещё не начатое создание цели, обнаружение ВМ после
  потерянного ответа создания. Состояние и ревизия миграции остаются прежними;
  управляющие запросы к имитации oVirt не отправляются просмотром.
- Браузерные проверки: источник включён/выключен/на паузе, начальное питание
  включено/выключено, включение вручную, отсутствующая и неизвестная цель,
  ошибка проверки, очистка незавершённой цели, активный перенос и группы.
- Снимки десктопа, телефона и тёмной темы просмотрены вручную.

Браузерные сценарии используют тестовые ответы API, серверные — имитацию oVirt.
Физическая отмена пользовательского переноса не выполнялась. Семантика действий
отмены не менялась: добавлены чтение состояний и подробное представление результата.
